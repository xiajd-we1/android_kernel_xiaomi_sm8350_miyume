======================================================

内核: 5.4.147 (venus / sm8350)

产物: out_venus/arch/arm64/boot/Image

一、方案结论（为什么不能直接用 tiann/KernelSU 最新源码）
-------------------------------------------------------
实测把官方 main（KSU_VERSION 32704）放进本 5.4 树编译，失败：

  drivers/kernelsu/feature/sucompat.c:8:10: fatal error:
      'linux/pgtable.h' file not found

5.4 没有 include/linux/pgtable.h（该头文件 5.8 才引入）。除此之外官方
main 还有结构性不兼容：

  1. 官方 kernel/Kconfig 里 KSU 带 depends on KPROBES && EXT4_FS，
     venus_defconfig 默认 CONFIG_KPROBES is not set，CONFIG_KSU 会直接消失。
  2. 官方已彻底移除 manual hook（KSU_MANUAL_HOOK）与 SUSFS：
     hook/ 下只剩 lsm_hook.c + tracepoint 那套，非 GKI 无路可走。
  3. 官方 hook 策略依赖 tracepoint syscall redirect，只支持 GKI 2.0
     （5.10+）；5.4 是 GKI 1.0。
  4. 官方 uapi 已到 6，且 manager 用 kernelUAPIVersion == managerUAPIVersion
     判定 isFullFeatured()，不等就把底部导航/模块页/预加载全部关掉。

因此内核侧继续用 BakaSU 作为实现引擎（它是唯一在 5.4 上能跑 manual/
inline hook + SUSFS 的分支），但把对外协议对齐到官方 uapi 6，
让官方管理器认为"这就是 KernelSU"。

二、本次改动（已应用并编译通过）
-------------------------------
uapi 协议对齐（关键，决定管理器能否正常识别）
  KernelSU/uapi/supercall.h
    - KERNEL_SU_UAPI_VERSION: 5 -> 6
    - 新增 struct ksu_lookup_symbols_cmd / KSU_IOCTL_LOOKUP_SYMBOLS ('K',22)
    - 新增 KSU_LOOKUP_SYMBOLS_MAX = 1024
    - 新增 KSU_GET_INFO_FLAG_PREINIT (1U << 5)
  KernelSU/uapi/feature.h
    - KSU_FEATURE_SHELL_SU_ADB_ONLY = 6
    - KSU_FEATURE_FLAG_SUPPORTED (1<<0) / KSU_FEATURE_FLAG_FORCED (1<<1)
  KernelSU/kernel/supercall/dispatch.c
    - do_get_feature: .supported 从 boolean 改为位掩码
    - 新增 do_lookup_symbols()，注册进 ksu_ioctl_handlers
  KernelSU/kernel/infra/symbol_resolver.{c,h}
    - 新增 ksu_lookup_kernel_symbols()：批量 kallsyms 解析，
      名称按 '$' / ".llvm." 截断，跳过模块符号，行为与 ksuinit 一致

品牌剥离（让管理器显示为 KernelSU，而不是 BakaSU）
  KernelSU/kernel/Kbuild
    - REPO_NAME := BakaSU -> KernelSU
  arch/arm64/configs/venus_defconfig
    - CONFIG_KSU_FULL_NAME_FORMAT="%TAG_NAME%-%KSU_VERSION%"
      （原为 %TAG_NAME%-%COMMIT_SHA%@%REPO_NAME%，会显示 ...@BakaSU 和 -dirty）
  KernelSU/kernel/manager/apk_sign.c
    - 签名表把 tiann/KernelSU 官方签名提到第一项（原本被
      CONFIG_KSU_MULTI_MANAGER_SUPPORT 包着放在 BakaSU 之后）；
      BakaSU/KOWX712 保留在 multi-manager 分支内
  KernelSU/kernel/include/klog.h
    - 去掉"把 pr_* 全部替换成 no_printk"的过度静默，恢复真实 printk，
      仅清空 pr_fmt 前缀（不再把 "KernelSU: " 打进 dmesg）

5.4 移植修复（保留上游验证过的行为）
  KernelSU/kernel/selinux/selinux.c
    - 清理重复注释造成的死代码块
  KernelSU/kernel/hook/setuid_hook.c
    - SUSFS 下首次 app spawn 时 cache_sid_if_needed()
      （5.4 non-GKI 上 cache_sid() 早于 policy 加载，否则 is_zygote() 恒假）
  KernelSU/kernel/feature/kernel_umount.c
    - 保留 5.4 开机安全保护：SUSFS 模式下不在此处 try_umount()
      （实测会与 app 自己的 mount-ns 竞争，导致 failed to attach
        + 卡 bootanimation）。隐藏由 susfs sus_path/sus_mount 负责，
        TIF 标记与 susfs_extra_works 仍照常执行。
